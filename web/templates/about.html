What is this?

This is the species metadata database behind BirdNET, the sound identification system developed at the Cornell Lab of Ornithology and Chemnitz University of Technology. It provides structured information about every species that BirdNET currently recognizes or may learn to identify in the future: common and scientific names, descriptions, images, and external identifiers, all accessible through a browsable website and a REST API.

Which species are included?

The database covers birds along with other animal groups that produce identifiable sounds: mammals, insects, amphibians, and reptiles. A few non-species sound classes, such as rain, thunder, engines, or chainsaws, are included as well.

For birds, we use AviList as our taxonomic authority. AviList is a global bird species checklist that reconciles and unifies major world bird lists. A bird must appear on the current AviList edition to be included in our database, under its AviList scientific name. iNaturalist taxa that AviList lumps into another species or treats as a subspecies are folded into that species and remain searchable as alternative names, except for a short reviewed list of forms kept as separate species (for example Hooded Crow). Species listed on AviList but not yet on iNaturalist are still included so that coverage stays as complete as possible. Species AviList lists as extinct are excluded.

For all other groups, we include species that have at least one sound recording documented on iNaturalist. Bats are an exception: they also qualify with at least 100 observations of any kind, since their calls are rarely recorded. Species with too little metadata (no image, no description, and hardly any external identifiers) are left out. Species flagged as extinct on iNaturalist are excluded from all groups.

Where do the data come from?

No single source covers everything we need, so we pull from several databases and combine the results. iNaturalist provides the backbone: taxon identifiers, common names in dozens of languages, default taxon photos, and the observation counts behind each species' commonness score. eBird contributes species pages, Macaulay Library images, and common names in over sixty regional language variants. Wikidata supplies its item IDs, external identifiers (GBIF, NCBI, Avibase, BirdLife), and Wikimedia Commons images with licensing information. Wikipedia provides species descriptions in about twenty languages, and a large language model (Gemini, OpenAI, or Claude, whichever is configured) translates or shortens descriptions where Wikipedia coverage is thin.

Each species is also cross-referenced against Macaulay Library, Xeno-Canto, and observation.org so that users can quickly find sound recordings and observations for any species in the database.

What does commonness mean?

Each species has a commonness score from 0 to 100. It ranks how often the species is observed on iNaturalist compared with the other species of its taxon group: 100 is the most observed bird (or mammal, insect, and so on), 0 the least. It describes how often people record a species, not how abundant it is in an area. Conspicuous, widespread, or easily photographed species score high, while abundant but secretive or remote species can score low. We compare within taxon groups because recording effort differs a lot between groups, for example birds and insects.

How are images chosen?

We try several sources in order and use the first image that meets our licensing requirements. The preference order is: the default taxon photo from iNaturalist (if it carries a Creative Commons license), then the species image from eBird and Macaulay Library, then Wikimedia Commons via Wikidata, and finally a Creative-Commons-licensed observation photo from iNaturalist as a last resort. For a small number of species we apply manual overrides when the automatically selected image is misleading or of poor quality.

Once selected, every image is downloaded, smart-cropped using object detection to keep the animal centered, and saved in two sizes as WebP files: a small thumbnail for the browse grid and a medium version for the species detail page.

For birds, we also reference the matching photo from Avicommons, a hand-picked collection of Creative-Commons-licensed bird photos, with its photographer and license. It is matched by eBird species code and kept only when Avicommons names the same species. We do not use it as our own image; it is listed as an alternative.

How do names and descriptions work?

Common names come from four sources that complement each other. For birds, the primary English name is taken from AviList, our taxonomic authority, ensuring consistency with the accepted species list. eBird provides additional regional name variants in other languages (for example, different Spanish names used in Argentina, Chile, and Mexico). iNaturalist adds community-contributed names in languages eBird does not cover. Wikidata labels fill remaining gaps. We merge all of these, giving preference to AviList for English bird names and eBird for other locales, and store them per locale so the API can return the right name for any supported language.

Descriptions follow a similar pattern. Native Wikipedia text comes first, cleaned of headings, reference lists, and subspecies lists. Where a language has no article, or only a stub, the language model translates the English description, using the species' established common name in that language. If no Wikipedia English text exists, the model writes an English description strictly from the species' other-language Wikipedia articles.

What is a BirdNET ID?

Every species in the database receives a stable BirdNET identifier, formatted as a five-digit number with a "BN" prefix. Birds use BN00001 to BN19999 (for example BN00483, the Mallard), other animals BN20000 to BN89999, and non-species sound classes such as rain or engines BN90000 to BN99999. Within each range, IDs were assigned in alphabetical order of scientific names at the last reassignment; species added later receive the next available number in their range. These identifiers let downstream systems reference a species without worrying about taxonomic name changes, and the mapping is stored persistently. Before the 1.0 release, identifiers may be reassigned as a documented breaking change when taxonomy cleanup requires it; after 1.0 they are meant to remain constant.

Licensing and reuse

The data, the images, and the code each have different terms.

  • Taxonomy data: the CSV and JSON files are licensed under CC BY-SA 4.0. You may share and adapt them, including commercially, if you give credit, indicate any changes, and distribute your adaptations under the same license.
  • Images: these are not part of the data files, which only link to them, and they are not covered by that license. Each image has its own: most are Creative Commons in various flavors, many of them non-commercial, and Macaulay Library images are copyrighted by their photographers and used under Cornell's terms. The license for each image is recorded in the dataset, so please check it before adding an image to your own codebase or product. For birds, the referenced Avicommons photos are an alternative: all are Creative Commons, although most are non-commercial.
  • Code: the code in the GitHub repository is licensed under the MIT License.

When you use the data, please credit the version you used: BirdNET+ Taxonomy {{ taxonomy_version }}, https://birdnet.cornell.edu/taxonomy, CC BY-SA 4.0. The data license file, also included in the ZIP download, lists the sources to credit.

The full dataset is available for download in CSV, JSON, and ZIP formats from the Download page, and programmatic access is provided through the REST API. Source code and documentation live on GitHub.
